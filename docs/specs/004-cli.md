# Spec 004 — Serviço e CLI

## Serviço (`servico.py`) — orquestra o pipeline; a CLI só chama isto
`processar(prompt, registro, client=None, dry_run=False, forcar=None) -> Resultado`
1. `forcar` informado → pula classificação/regras (confiança 1.0, motivo "forçado").
2. Senão: `classificar` -> `rotear`.
3. `dry_run` → não chama o modelo escolhido, mas registra a decisão.
4. Registra sempre no SQLite e devolve `Resultado(id, decisao, caracteristicas, resposta|None)`.

## CLI (`cli.py`, typer) — comando `router`
- `router rotear "PROMPT" [--dry-run] [--forcar haiku|sonnet|opus] [--db CAMINHO]`
  - imprime modelo, confiança, motivo, resposta e tokens; depois pergunta `Acertou? (s/n)`; se `n`, pergunta o modelo preferido.
- `router historico [--limite N]`
- `router feedback ID s|n [--preferido MODELO]`
- `router calibrar` — taxa de acerto por modelo, erros recentes e alerta quando um modelo erra >30% com >=10 amostras.

## Aceite
- Testes do serviço e da CLI sem rede (fakes/monkeypatch).
- Erros esperados (chave ausente, modelo inválido) → mensagem curta + exit code 1, sem traceback.
